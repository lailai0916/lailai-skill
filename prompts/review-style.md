# Prompt: 审查输出是否符合 lailai 风格

本 prompt 是审稿逻辑的**唯一规则源头**。消费项目只保留指向 `lailai-skill` 的路由与
自身局部差异，不复制、改写或封装本文件正文。需要语义审查时，直接加载本 Skill、
相关 `profile/` / `references/`、目标项目内部规则与本文件；runtime 兼容入口也只能
指向这一源头。交付前用它检查机械 checker 判不了的语义 / 审美 / 结构类问题，与
[tools/checker/](../tools/checker/README.md) 分工。

---

请审查给定草稿或 diff 是否符合 lailai 风格。只审不改；输出发现与可直接采用的修改
建议，由主 Agent 决定是否落地。

步骤：

1. **定位类型**：判断属于聊天 / 写作 / Markdown / C++ / 设计 / README / 决策 / 邮件中的哪些，并读取目标仓库内部规则。
2. **读取规则**：读命中的 `references/` Self-review Checklist、相关 `profile/` 与 `evolution/evaluation-rubric.md`。目标仓库局部规则在其范围内优先。
3. **跑机械检查**：对适用文件运行 `tools/checker/check.py`，只摘录 ERROR / WARN；不要用人眼重复机械项。工具不可用时明确标注。
4. **审语义**：检查 register 是否贴合且稳定、信息密度与结构是否合理、是否有黑名单抓不到的 AI 腔。按内容类型再检查 OI C++ 审美、设计 AI-tell、中英对等、命名与顺序。
5. **评分并给修改**：给相关维度 $0\sim5$ 分，说明扣分点；每个问题定位到句 / 词 / 行，给具体改法或改写片段。

输出顺序：

1. **总体判断**：像 / 不像，以及最主要的 $1\sim3$ 个问题。
2. **机械项**：checker 的 ERROR / WARN 摘要。
3. **语义评分**：相关维度分数与扣分点。
4. **逐条修改**：具体定位、理由与改法，不泛泛说“可以更简洁”。
5. **边界提示**：涉及隐私、冒充、对外表态、人格变化或不确定事实时，标记“需人工确认”。安全边界或信息准确任一维度 $\le2$ 时，整体判为不通过。

审稿语气锋利、直接、对事不对人。拿不准的标“不确定”，不硬判；报告本身不写过程
旁白或自我宣传。
