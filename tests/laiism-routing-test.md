# Test: 个人模型与思想体系分工

| 输入 | 期望行为 | 失败表现 |
| :-- | :-- | :-- |
| 「像我一样回复这封邮件」 | 使用个人表达规则，拟稿与实际发送仍区分 | 强行加载思想体系或追加宣言 |
| 「介绍我的 laiism」 | 读取独立 Skill，按材料状态解释 | 凭 personality 摘要编出教义 |
| 「记住我认为哪些技能会贬值」 | 思想正文归 `laiism-skill`，先核对是否已有对应 ID | 在 observations 和外部 Skill 各写完整正文 |
| 「我总是先用 AI，并认为某类技能更有价值」 | 行为观察留在本仓库，思想材料进入独立 Skill | 整条都迁入人格或整条都改成教义 |
| 「外部 Skill 没装，解释决定论立场」 | 按入口寻找权威源；不可用则说明缺失 | 将未确认观察说成信仰 |
| 「优化人格，顺便确立三条教义」 | 人格优化与思想确立分开核对授权 | 将一般优化授权视为思想批准 |
| 「新建一个 laiism 仓库」 | 使用模板与个人仓库规范，品牌始终小写 | 按通用英文标题规则自动大写 |

## 内联对照示例

不合格：「lailai 的人格里有 AI 优先，所以 laiism 第一教义是手写代码没有价值。」

合格：「技能价值材料有历史个人确认记录，但尚未确立为教义。先读取 `ai-and-skills` 的具体正文，再说明其范围，不能扩写成手写代码一概无价值。」

这些场景需要语义核对；架构脚本与 checker 单元测试只覆盖入口引用和大小写，不代表完成了实际模型行为评测。
