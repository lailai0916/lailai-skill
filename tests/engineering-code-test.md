# Test: 工程代码风格（注释与约定）

## 测试目标

验证工程代码（TS / React / CSS）的注释与约定符合 lailai 习惯：注释解释「为什么」、少而精、无 banner / TODO / 注释掉的代码、无 ASCII 分隔线。

## 输入任务

给被测 AI 一段带问题的 TSX 片段——含复述代码的注释（`// increment i`）、文件头 banner（作者 / 日期）、一段被注释掉的旧代码、一条 `// TODO: 优化`、一条 `// ===== Section =====` ASCII 分隔线、以及一处非显然的 workaround 却没注释。要求审查并改写注释与区段标签。

## 期望输出特征

- 删除复述代码的注释、banner、注释掉的代码、TODO。
- 给非显然的 workaround 补一行「为什么」注释（英文、句首大写）。
- ASCII 分隔线换成独占一行的纯名词短语标签（`// Variants`）。
- 只微调注释与约定，不重排无关代码（编辑而非重写）。

## 评分标准（0～5）

- 0：保留 banner / TODO / 注释掉的代码，或新增更多复述型注释。
- 3：清掉大部分噪音，但漏一类（如留了 TODO 或没给 workaround 补 why）。
- 5：噪音全清、workaround 有 why、区段标签规范、改动最小。

## 常见失败表现

- 保留或新增 `// set state`、`// return result` 等复述注释。
- 保留文件头 banner、作者 / 日期、变更记录。
- 把 TODO 留在注释里而非移入任务清单。
- 用 `// ----` / `// ====` 分隔线；顺手重排无关代码。

## 客观检查项（可机械判定，全过才算通过）

- [ ] 无复述代码的注释（`// increment i`、`// set state` 一类）。
- [ ] 无 banner / 文件头 / 作者 / 日期 / 变更记录注释。
- [ ] 无注释掉的代码块、无 `TODO` / `FIXME`。
- [ ] 无 ASCII 分隔线（`──` / `====` / `----` 成行）。
- [ ] 非显然的 workaround 有一行「为什么」注释，英文、句首大写。
- [ ] 区段标签是独占一行的纯名词短语。

## 通过条件

主观评分 ≥ 4 分，**且**上述客观检查项全部通过。
